# 部署指南（展惠进销存）

> 适用版本：v0.5.2 起。本文只讲部署与安全配置，不讲业务操作。
> 文中所有密钥均以占位符表示，**请勿把真实密钥写进本文档、代码仓库、聊天记录或工单**。

## 1. 先说结论：默认只能本机用

- 服务默认只监听本机回环地址（`127.0.0.1`），不设 `ORANGE_BIND` 时外网无法访问。
- 默认令牌签名密钥是源码里公开的内置固定值，**仅限本机自用**。一旦服务离开本机（局域网、公网、内网穿透隧道、反向代理），任何人都能用这个公开值伪造管理员令牌，接管全部账套。
- 因此：**部署到非本机之前，必须先设置强随机密钥**（见第 2 节）。这不是可选项。

## 2. 非本机部署前必须做的两件事

### 2.1 生成并设置强随机 `ORANGE_JWT_SECRET`

生成一个 32 字节（64 位十六进制字符）的随机串（每次运行结果都不同，请使用你自己运行命令得到的输出）：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

把输出作为 `ORANGE_JWT_SECRET` 的值。要求：

- 长度至少 32 位随机字符，不要用单词、生日、公司名等可猜内容；
- 每个部署实例用不同的密钥，不要多处复用同一个；
- 密钥只放在部署环境的变量/密钥管理里，**不要写进代码、不要提交到仓库**。

设置方法（任选其一，按你的部署方式）：

```powershell
# Windows PowerShell（当前会话有效；启动器/服务要在同一会话里启动才生效）
$env:ORANGE_JWT_SECRET="<把尖括号及内容替换为你生成的随机串>"
```

```powershell
# Windows PowerShell（永久写入当前用户环境变量，重启后仍生效，需重新打开终端）
[Environment]::SetEnvironmentVariable('ORANGE_JWT_SECRET', '<你生成的随机串>', 'User')
```

```bash
# Linux / macOS（当前会话有效）
export ORANGE_JWT_SECRET="<你生成的随机串>"
```

### 2.2 设置 `ORANGE_REQUIRE_SECRET=1`

```powershell
# Windows PowerShell
$env:ORANGE_REQUIRE_SECRET="1"
```

```bash
# Linux / macOS
export ORANGE_REQUIRE_SECRET="1"
```

作用：强制校验——启动时若未设置 `ORANGE_JWT_SECRET`，服务直接**拒绝启动**而不是静默回落到内置默认密钥。这样一次漏配环境变量就会在启动时立刻暴露出来，而不是等到被攻击时才发现。

> 建议：所有非本机部署都同时设置这两项；只设密钥、不设 `ORANGE_REQUIRE_SECRET=1` 时，万一某次部署丢了密钥变量，服务仍会用内置密钥跑起来。

## 3. 暴露到公网 / 隧道前的检查清单

按顺序逐项确认，缺一项都不要暴露：

1. `ORANGE_JWT_SECRET` 已设为强随机值（第 2.1 节），且与内置默认值不同。
2. `ORANGE_REQUIRE_SECRET=1` 已设置（第 2.2 节）。
3. 明确你确实需要暴露：默认只监听本机是最安全的；只有确认需要局域网/公网访问时，才设置 `ORANGE_BIND=0.0.0.0`（监听全部网卡）或走隧道/反向代理。
4. 若绑定了非本机地址（`ORANGE_BIND=0.0.0.0` 或其它非 loopback 地址）但未设置有效密钥，服务启动时会直接报错退出——这是保护机制，不是故障；按第 2 节配好密钥再启动。
5. 隧道/反代场景下，如需用自定义域名访问，域名须加入 Host 白名单（`ORANGE_ALLOW_HOSTS`），否则请求会被拒绝；不要为了省事放宽白名单。
6. 确认防火墙/云安全组只放行你需要的端口，不要全端口放行。

启动后自查：服务日志里不应再出现“未设置 `ORANGE_JWT_SECRET`，将使用内置本地密钥”的安全提示；出现该提示说明密钥没生效（变量没进服务进程的环境），请先停掉暴露、修好配置再开放访问。

## 4. 换密钥：旧令牌自动失效，用户需重新登录

- 令牌有效期为 7 天，签名密钥就是 `ORANGE_JWT_SECRET`。
- **更换 `ORANGE_JWT_SECRET` 后，所有用旧密钥签发的令牌立即失效**，无需逐个吊销；所有已登录用户都会被登出，需要重新登录。
- 适用场景：密钥疑似泄露、人员变动、把一台曾用默认密钥暴露过的实例收回来重新加固。
- 操作：停服务 → 换成新的强随机密钥（第 2.1 节命令重新生成）→ 重启服务 → **提前通知所有用户重新登录**。
- 注意：换密钥不影响账套数据本身，只影响登录态；但如果旧密钥已泄露且攻击者已用伪造令牌做过写操作，换密钥后还须检查账套数据有无异常改动。

## 5. 端口与绑定

- 端口：`PORT`（服务端）/`ORANGE_PORT`（启动器），默认 `7741`，合法范围是 **1–65535 的整数**；非法值（如 `abc`、`99999`、`0`）启动时直接报错退出，请改成合法端口再启动。
- 绑定：默认 `127.0.0.1`（仅本机）；`ORANGE_BIND=0.0.0.0` 表示监听全部网卡。改绑定即改暴露面，改之前先完成第 2 节。

## 6. 常见错误

| 现象 | 原因与处理 |
| --- | --- |
| 启动报错“已设置 `ORANGE_REQUIRE_SECRET=1` 但未设置 `ORANGE_JWT_SECRET`” | 按第 2.1 节设置密钥后再启动 |
| 启动报错“绑定地址为非本机，但未设置有效的 `ORANGE_JWT_SECRET`” | `ORANGE_BIND` 为非本机地址时必须配强随机密钥；或改回默认本机绑定 |
| 日志出现“未设置 `ORANGE_JWT_SECRET`，将使用内置本地密钥” | 密钥变量没进服务进程环境（例如只在别的终端窗口里 `export`）；请在启动服务的同一环境里设置，或写入永久环境变量后重启终端再启动 |
| 换密钥后所有人被登出 | 预期行为（第 4 节），通知用户重新登录即可 |
| 隧道域名访问被拒绝（421） | 域名未进 Host 白名单，见第 3 节第 5 项 |
